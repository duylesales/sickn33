"Can we export our data?" is one of the most common questions B2B buyers ask before signing. Sometimes they want reports in Excel. Sometimes they need data for their own analysis or another system. Often the real question is about trust: if this startup disappears or we decide to leave, can we take our data with us?

The question also comes from law and procurement. GDPR gives individuals a right to data portability for certain data. Government and enterprise contracts often include exit clauses requiring the supplier to return all customer data in a usable format. Financial customers under DORA must have exit strategies for their ICT suppliers.

AI-built apps often have a basic "Export CSV" button on one or two tables, generated by a prompt, that downloads what is on the screen. That is useful, but it is not a data export strategy. This guide explains how to build exports that satisfy users, buyers and auditors.

## Key Takeaways

- **There are three kinds of export:** quick exports of a list on screen, full account exports for exit and portability, and API access for ongoing integration.
- **Full exports should include all customer data,** including related records and uploaded files, in documented formats.
- **Generate large exports in the background** and deliver them through secure, expiring download links.
- **Protect against CSV injection** and handle Excel's regional quirks, especially for Dutch users.
- **Restrict exports to the right roles and record them in the audit log,** because exports are a common data leakage path.

## Three Kinds of Export

| Type | Purpose | Typical format | Who uses it |
| --- | --- | --- | --- |
| List export | Get the data currently shown, filtered, into Excel | CSV or XLSX | Everyday users |
| Full account export | Get all data out for backup, migration or exit | ZIP with CSV or JSON files plus attachments | Admins, procurement, offboarding |
| API access | Ongoing synchronisation with other systems | JSON via API | Developers and integrations |

Each serves a different need. Most B2B products need the first two; the third becomes important as customers integrate more deeply. Our guide on [offering an API to SaaS customers](https://launchstudio.eu/en/blog/how-do-i-offer-an-api-to-my-saas-customers) covers the API.

## List Exports Done Well

List exports should:

- **Respect filters and sorting** the user applied
- **Export all matching rows,** not only the current page, which AI-generated code often gets wrong
- **Respect permissions,** exporting only data the user may see, enforced on the server
- **Use readable column headers,** in the user's language
- **Format dates and numbers sensibly,** or provide raw values in a consistent format

For more than a few thousand rows, generate the file on the server, ideally in the background, rather than building it in the browser from loaded data.

## Full Account Exports

A full export is what procurement teams mean when they ask about exit. It should contain:

- **Every table with customer data,** one file per entity, such as contacts, projects, invoices and notes
- **Relationships preserved** through stable IDs, so related records can be linked after import elsewhere
- **Uploaded files,** such as documents and images, organised in folders referenced from the data files
- **A data dictionary** explaining each file, column, type and relationship
- **Metadata:** export date, organisation, version of the export format

JSON preserves nested structures and types well; CSV is easier for non-technical users. Many products include both, or CSV for tabular data and JSON for complex objects.

## Generating Exports in the Background

Full exports and large list exports can take seconds or minutes. Do not generate them in a request handler that may time out. Instead:

1. The user requests an export.
2. The app creates an export job record and returns immediately, showing "Your export is being prepared".
3. A background worker queries data in batches, writes files, packages them and uploads the result to private storage.
4. The job record is updated with status and file location.
5. The user receives a notification and downloads the file through a signed link.
6. Export files are deleted automatically after a period, such as seven days.

This approach handles large accounts, avoids timeouts and keeps the app responsive.

## Secure Downloads

Export files contain everything, so they deserve the strongest protection:

- **Store them in a private bucket,** never a public one.
- **Use signed download URLs** with short expiry, and generate them only for the user who requested the export or other authorised admins.
- **Delete files after a set period.**
- **Consider requiring re-authentication** or MFA before generating full account exports.

## CSV Injection

CSV injection, also called formula injection, is a well-known risk. If a cell value starts with characters such as `=`, `+`, `-` or `@`, spreadsheet programs may interpret it as a formula when the file is opened. A malicious user could enter a value like a formula in a name field, and when an admin opens the export in Excel, the formula runs, potentially extracting data or triggering external requests.

OWASP recommends prefixing such values, for example with a single quote, or otherwise escaping them, for any field that could contain user input. This is easy to implement in your export code and often forgotten in AI-generated exports.

## Dutch Excel Quirks

CSV is a simple format, but Excel's interpretation depends on regional settings. Dutch users often encounter:

- **Delimiter issues:** Excel with Dutch settings typically expects semicolons rather than commas as separators, so comma-separated files open with everything in one column.
- **Decimal separators:** Dutch number formatting uses commas for decimals, which conflicts with comma-delimited files.
- **Character encoding:** names with characters such as é, ë or ij may appear garbled unless the file is UTF-8 with a byte order mark, which Excel uses to detect encoding.
- **Dates:** ambiguous date formats are misread.

Practical options: offer XLSX exports alongside CSV, generate CSV with semicolons for Dutch locale users, include a UTF-8 byte order mark and use unambiguous date formats such as ISO 8601. Test exports by opening them in Excel with Dutch settings.

## Access Control and Audit Logging

Exports are one of the most common ways data leaves an organisation, intentionally or not. Protect them:

- **Restrict full exports to admins** or a dedicated role.
- **Enforce permissions on the server** for list exports, exporting only rows the user may access.
- **Record every export in the audit log:** who, what, when, how many records.
- **Alert on unusual exports,** such as very large exports by non-admin users.
- **Consider limits** on export frequency to prevent abuse.

## GDPR Data Portability

Under GDPR Article 20, individuals have a right to receive personal data they provided to a controller, in a structured, commonly used and machine-readable format, where processing is based on consent or contract and carried out by automated means. For a B2B SaaS, your customer is often the controller for their end users' data and you are the processor, so the customer handles such requests, but they need your export tools to do so. For your own users, such as account holders, you may be the controller.

Practical steps:

- **Offer per-person exports** where your product holds data about individuals, such as a client or employee profile with related records.
- **Use machine-readable formats** such as JSON or CSV.
- **Document how customers can fulfil requests** using your tools.

## Scheduled Exports and Reporting Needs

Some customers do not want to click "Export" every week; they want data delivered automatically to their own reporting tools, data warehouse or shared drive. Before building custom integrations for each customer, consider offering:

- **Scheduled exports,** such as a weekly CSV of new orders or a monthly full export, delivered through a secure link by email or uploaded to a storage location the customer controls.
- **Report templates** for the exports customers request most often, with consistent columns so their spreadsheets and dashboards keep working.
- **Incremental exports** that include only records changed since the last export, which keeps files small and processing fast.
- **Webhooks or API access** for customers who need near real-time data.

Ask customers what they actually do with exported data. Often, a few recurring needs, such as monthly figures for the board or data for the accountant, can be met with a well-designed report rather than raw exports.

## Exit and Offboarding

When a customer leaves, contracts often require:

- A complete export within a defined period
- Support during migration, sometimes paid
- Deletion of data after confirmation, with a deletion confirmation

Build the full account export first, then define your offboarding process: when exports are available, how long data is kept after cancellation and how deletion is confirmed. Clear exit terms make procurement easier.

## Testing Exports Before Customers Do

Export bugs are often discovered at the worst moment: during an audit, a migration or a dispute. Test exports deliberately with realistic data, including large accounts, records with special characters, empty fields, very long text, multiple currencies and attachments. Open the files in Excel with Dutch and English settings, in Google Sheets and in a text editor, and try importing a full export into a fresh database to confirm that relationships survive. A test that round-trips data proves the export is genuinely usable, not just downloadable.

## Common Mistakes in AI-Built Apps

**Exporting only the visible page.** Users think they exported everything.

**Client-side exports of all data.** Loading entire tables into the browser to build a CSV, which is slow and may bypass server-side permission checks.

**Public storage for export files.** Anyone with the link can download a full dataset.

**No CSV injection protection.**

**Excel-unfriendly files** for Dutch users.

**No audit trail** of who exported what.

## Frequently Asked Questions

### Do I have to offer data exports in my SaaS?

In practice, yes for B2B products. GDPR data portability rights, procurement exit clauses and customer trust all require a way to get data out. Even without a legal obligation in a specific case, buyers increasingly treat export capability as a basic requirement.

### What format should a full data export use?

Use documented, machine-readable formats: CSV for tabular data that users open in spreadsheets, JSON for complex or nested data, and the original files for uploads, packaged together with a data dictionary explaining the structure.

### What is CSV injection?

CSV injection occurs when a value in an exported file starts with characters such as `=`, `+`, `-` or `@` and a spreadsheet program interprets it as a formula. Escaping such values during export, as recommended by OWASP, prevents formulas from executing when the file is opened.
