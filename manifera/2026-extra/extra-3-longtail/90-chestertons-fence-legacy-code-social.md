A new engineer at a Constanța retailer removed a "redundant" currency-rounding check during routine cleanup. Two weeks later: a rounding bug hit customer refunds during a promo pricing event — the exact bug that check had silently prevented for 3 years. 🚧

G.K. Chesterton, 1929: if you see a fence in a field with no obvious purpose, don't remove it until you find out why it's there. The reason might be sound even if it's invisible from where you're standing. Software engineers adopted the principle for exactly this reason — confusing code is often a fix for a problem that hasn't recurred BECAUSE the fix is still there.

A buried support ticket confirmed: nearly identical incident, 3 years earlier. Nobody had written down why the fix existed.

Now: mandatory history check before removing anything confusing, and every non-obvious fix gets a comment explaining why.
